ThreadLocal回顾

1. 核心作用

  • 数据隔离：为每个线程提供独立的变量副本，无需加锁即可实现线程安全（以空间换时间）。
  • 上下文透传：在同一线程的深层方法调用链中隐式传递数据（如 TraceId、UserContext）。

2. 底层结构

数据存放在 Thread 内部，而非 ThreadLocal 对象中。

  • Thread ──持有──> ThreadLocalMap ──包含──> Entry[]
  • Entry：Key 为对 ThreadLocal 的弱引用；Value 为实际存放的数据（强引用）。

3. 核心 API

  • set(T value)：以当前 ThreadLocal 为 Key，存入当前线程的 Map 中。
  • get()：从当前线程的 Map 中提取对应的 Value。
  • remove()：清理当前线程 Map 中对应的 Entry（使用完毕必须调用）。

4. 内存泄漏与解决方案

  • 原因：ThreadLocal 被 GC 回收后，Key 变为 null；但线程池中的长生存期线程依然强引用着 Value，导致无用数据无法回收。
  • 规范：使用完后必须在 finally 块中调用 remove() 显式清理。

SnapshotThreadLocal

1. 核心设计理念

SnapshotThreadLocal是一个轻量级、无锁的线程局部存储容器，其核心设计思想可以概括为：AtomicReference（原子引用）+ 不可变的升序并行数组（ThreadMap）+ Copy-on-Write（写时复制）。

设计精妙之处：ThreadMap 是不可变的，一旦创建，其内部的数据就永远不会被修改。这意味着多线程同时读取 ThreadMap 时，绝对不需要加锁，也不用担心读到中途被破坏的脏数据。

3. 内部读取原理（get() 机制）

当在某个线程中调用 get() 时，执行流程极其高效：

  1. 获取当前线程 ID：调用 Thread.currentThread().id，拿到一个 long 类型的线程唯一标识。
  2. 获取当前 Map 实例：直接通过 map.get() 从 AtomicReference 中取出当前不可变的 ThreadMap（无锁、无等待）。
  3. 升序数组二分查找：
    在 ThreadMap.keys（long[]）上使用标准的二分查找算法（Binary Search），寻找 Thread.id 所在的索引位置 $i$：
    • 若找到 i>=0，直接返回 values[i]。
    • 若未找到，返回 null。

读取设计的内部优势

  • 零内存分配（Zero Allocation）：整个读取过程不需要 new 任何对象，对垃圾回收（GC）零负担。
  • 极速寻址：在现代 CPU 架构下，对连续内存的原生数组（long[]）进行极小规模的二分查找，CPU 缓存命中率极高，指令执行极其迅速。

4. 内部写入与清理原理（set(value) / 节点移除机制）

当在某个线程中调用 set(value) 时，由于 ThreadMap 是不可变的，内部采用 写时复制（Copy-on-Write） 与 CAS 自旋重试 策略：

  1. 读取当前状态：获取当前线程 ID (targetId) 和 AtomicReference 中最新的 oldMap。
  2. **构建全新的 ThreadMap**：
    • 情况 A（更新）：若 targetId 已存在于 oldMap.keys 中：
      • 若 value != null，复制一份旧数组，仅将对应索引位置的 values 替换为新值（长度保持 $N$）。
      • 若 value == null，触发缩容逻辑，创建一个长度为 $N - 1$ 的新数组，将当前线程的数据彻底剔除。
    • 情况 B（新增）：若 targetId 不存在：
      • 若 value == null，无需处理，直接返回原 Map。
      • 若 value != null，创建一个长度为 $N + 1$ 的新数组，将旧数据复制过来，并将 targetId 按升序插入到正确的位置，生成一个新的 newMap。
  3. CAS 原子替换：
    调用 map.compareAndSet(oldMap, newMap)：
    • 成功：新 Map 挂载成功，写入或清理完成。
    • 失败：说明在构建新 Map 的微秒级时间差内，有其他线程抢先更新了 map。此时进入 do-while 自旋，读取最新的 oldMap 并重试上述步骤。

与 Java 标准 ThreadLocal 机制对比

比较维度 Java 标准 ThreadLocal Compose SnapshotThreadLocal
底层数据结构 开放寻址法散列表（ThreadLocalMap）+ WeakReference 不可变升序原生数组（long[] + Object[]）
读取性能与算法 哈希寻址（需处理哈希冲突与废弃 WeakReference 节点） 无锁二分查找（在极小线程集下指令少、CPU Cache 命中率高）
内存与 GC 消耗 依赖弱引用防止泄漏，增加 GC 追踪负担 无弱引用，结构紧凑，读取阶段零对象分配（Zero Allocation）
更新与写入机制 原位修改（In-place），频繁扩容与再哈希开销 写时复制（Copy-on-Write） + CAS 自旋，写慢读极快
适用场景定位 通用并发场景，支持任意线程规模与频繁读写 极端高频读、极低频写、小规模线程池（如 Compose 快照渲染系统）
